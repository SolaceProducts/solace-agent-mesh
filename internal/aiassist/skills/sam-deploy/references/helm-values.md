# Helm Values Reference

These are the load-bearing keys you actually set, organized by capability with corrected go-only 2.x chart defaults; the full schema and every default live in the **Helm Values Reference** doc and in the `values.yaml` inside the downloaded chart bundle — read those for anything not named here.

| Concern | Keys | Notes |
|---|---|---|
| Images & registry | `global.imageRegistry` (default `gcr.io/gcp-maas-prod`); `global.imagePullKey` **or** `global.imagePullSecrets`; `samDeployment.gwe.image.*`, `samDeployment.awe.image.*`, `samDeployment.str.image.*` | `imagePullKey` is applied with `--set-file` and creates a `kubernetes.io/dockerconfigjson` Secret; `imagePullSecrets` is a list of existing secret names. The two are **mutually exclusive**. GWE repo is `solace-agent-mesh`; AWE inherits GWE; **STR is `solace-agent-mesh-str` and must NOT inherit GWE** — it carries both the Go and Python tool runtimes. |
| Broker | `global.broker.embedded` (default `true`); `broker.url`, `broker.vpn`, `broker.clientUsername`, `broker.password` | `embedded: true` runs the bundled embedded broker — the **single heaviest component** (≥ 2480 MiB). Set `false` for an external broker and fill the `broker.*` connection fields — `broker.url` is `tcps://...:55443` or `wss://...:443`. Sizing tracks which heavy components are enabled, not a flat number: full quickstart needs ~16 GiB, but external broker + bundled persistence is workable on ~8 GiB (see helm-quickstart.md). |
| Persistence | `global.persistence.enabled` (default `true`); `global.persistence.namespaceId` (default `solace-agent-mesh`); `dataStores.database.*`; `dataStores.objectStorage.type`; `dataStores.objectStorage.workloadIdentity.enabled`; `dataStores.s3.*` / `dataStores.azure.*` / `dataStores.gcs.*` | `enabled: true` bundles PostgreSQL + object storage. **`namespaceId` is triple-duty: it scopes the DB/users, is the broker topic prefix** (sets the `NAMESPACE` env var)**, and, when `enabled: true`, is the object-storage (S3) bucket name** (with external stores the bucket is `dataStores.s3.bucketName`). The chart schema enforces `^[a-z]([a-z0-9-]*[a-z0-9])?$`, 3–40 characters: start with a lowercase letter, then lowercase letters, digits, and hyphens only (no dots, no underscores), ending in a letter or digit. `helm install`/`upgrade` rejects anything else before any pod starts. Mirror the hyphenated default `solace-agent-mesh`. On a shared broker (e.g. Solace Cloud) the default collides on topics with any other default install — set a value unique among everyone on that broker. Changing it later re-prefixes topics **and** points Agent Mesh at fresh, empty databases. For external stores set `enabled: false`: `dataStores.database.*` = host, port `5432`, adminUsername, adminPassword, applicationPassword, supabaseTenantId; `dataStores.objectStorage.type` is `s3`/`azure`/`gcs` with the matching per-provider block. |
| LLM | `llmService.llmServiceEndpoint`, `llmService.llmServiceApiKey`; `llmService.planningModel`, `generalModel`, `reportModel`, `imageModel`, `transcriptionModel` | The model alias keys are seeds and may be left empty — operators add models in the Console later. |
| Tool API keys | `toolApiKeys.*` (e.g. `anthropic`, `gemini`, `google`, `googleSearchApiKey`, `googleCseId`) | Empty values are omitted from the rendered Secret. |
| Auth (OIDC/RBAC) | `sam.authorization.enabled` (default `false`); `sam.oauthProvider.oidc.issuer` / `clientId` / `clientSecret` / `scopes`; `sam.dnsName`; `sam.sessionSecretKey`; `sam.oauthProvider.providerName` / `claimKey`; `sam.authenticationRbac.users[]`, `sam.authenticationRbac.disableBuiltinRoles` | With `authorization.enabled: false` every user is admin. `sam.dnsName` drives the OIDC redirect URI host. `sessionSecretKey` is auto-generated and stable if left empty. `authenticationRbac` accepts only `users[]` (seed the bootstrap admin) and `disableBuiltinRoles` (suppresses the built-in `sam_admin` role); any other key fails schema validation. Custom roles, role assignments, IdP claim mappings, and default roles are managed as code with `sam config apply`, not Helm values. `oauthProvider.claimKey` is the deployment-wide token claim for claim mappings (empty = `groups`; set `roles` for Microsoft Entra app roles). If the IdP returns that claim only for a dedicated scope (commonly `groups`), request it: on a chart that has a `sam.oauthProvider.oidc.scopes` list, set that (the chart refuses a list without `openid`); on a chart without it (check `helm show values`; adding an unknown key there fails schema validation), set `environmentVariables.OIDC_SCOPES` to the full space-separated list including `openid`. Either way the list replaces the default `openid email profile offline_access`, and never set both (the chart fails to render). Either route needs Agent Mesh 2.569.0+ in the Entrypoint (`samDeployment.gwe.image.tag`); an older image ignores it silently. Chart 2.4.1+ installs 2.569.0; chart 2.4.0 has the key but installs 2.568.3. |
| Networking | `service.type` (default `ClusterIP`); `ingress.enabled`, `ingress.className` (`nginx`/`alb`/`traefik`/`gce`), `ingress.host` (default `""`), `ingress.autoConfigurePaths` (default `true`), `ingress.tls`; `sam.dnsName`; `sam.cors.allowedOriginRegex` | Set `ingress.host` to the external hostname (usually the same value as `sam.dnsName`) — it defaults to empty. Leave `autoConfigurePaths` on. `cors.allowedOriginRegex` defaults to localhost-only — set your real origins in production. |
| Environment variables | `extraSecretEnvironmentVars` (list); `environmentVariables` | `extraSecretEnvironmentVars` sources env vars from existing Kubernetes Secrets — use this for secrets. `environmentVariables` renders to a ConfigMap in **plaintext** — non-secret only; put `HTTP_PROXY` / `HTTPS_PROXY` here for proxied / air-gapped egress. |
| Deployment / rollout | `samDeployment.rollout.strategy` (default `RollingUpdate`, the only supported value); `samDeployment.serviceAccount.name` / `.annotations`; `samDeployment.azureWorkloadIdentity.enabled` / `.audience` (default `false` / `api://AzureADTokenExchange`); `samDeployment.customCA.enabled` / `.configMapName` (default `truststore`); `samDeployment.mcpConnectorTLS.enabled` / `.secretName` / `.mountPath` (default `false` / `""` / `/etc/sam/mcp-tls`); `samDeployment.gwe.resources` / `samDeployment.awe.resources` / `samDeployment.str.resources` | `strategy` is `RollingUpdate` with `maxSurge: 0`, which replaces the single-replica pod in place. GWE, AWE and STR share one service account (`serviceAccount.name`, default `<release>-solace-agent-mesh-sa`); its annotations carry object-storage workload identity, and the render fails if annotations or `dataStores.objectStorage.workloadIdentity.enabled` are set without a name. `azureWorkloadIdentity.enabled` mounts the token that lets Microsoft Foundry models sign in with Azure Workload Identity. `mcpConnectorTLS.enabled` mounts the Secret named by `secretName` (PEM files; it must exist in the release namespace and hold at least one file) read-only at `mountPath` on the GWE and AWE pods and sets `SAM_MCP_CONNECTOR_TLS_DIR` on GWE only, so an MCP connector's `ssl_config` paths can lie inside it; the render fails if `mountPath` is, or is a parent of, a path the pods already use (`/tmp`, `/app/data`, `/etc/sam/configs/...`, `/etc/ssl/certs`). After the Secret changes, `helm upgrade` restarts AWE only when the chart can read the Secret from the cluster, otherwise `kubectl rollout restart` it; GWE needs no restart, because the Platform service rereads the files on each use. Resources are set per component (there is no `samDeployment.resources`); defaults are modest requests with a 4-CPU limit — raise requests for real load. |
| Validations | `validations.clusterResourceChecks` (default `true`) | Template-time checks that referenced Secrets/ConfigMaps/StorageClass/IngressClass exist; needs `get` RBAC. Disable to skip. |
| Pre-flight | `samDoctor.enabled` (default `true`), `samDoctor.failOnError` (default `true`), `samDoctor.timeoutSeconds` (default `180`), `samDoctor.tlsDnsName` (defaults to `sam.dnsName`) | Failed runs are retained — read their logs. |

For the full schema and every default, see the **Helm Values Reference** doc, or read `values.yaml` in the downloaded chart bundle.
